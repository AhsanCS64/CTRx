1. Environment variables (backend/.env.example)

   APP_ENV=development
   LOG_LEVEL=INFO
   DATABASE_URL=postgresql+psycopg://ctrx_app:<Kushal999>@localhost:5432/ctrx_db
   TEST_DATABASE_URL=postgresql+psycopg://ctrx_app:<Kushal999>@localhost:5432/<test_db_I_create>
   JWT_SECRET_KEY=            # signs tokens
   JWT_ALGORITHM=HS256
   ACCESS_TOKEN_EXPIRE_MINUTES=15
   REFRESH_TOKEN_EXPIRE_DAYS=7
   HMAC_SECRET=               # keyed hash for identity-number lookups
   ENCRYPTION_KEY=            # Fernet key for identity numbers at rest
   CORS_ORIGINS=http://localhost:5173
   STORAGE_DIR=./storage      # PDFs and application documents (local-disk storage)
   VERIFY_BASE_URL=           # fallback only; system_settings 'verify.base_url' wins when set

   Frontend (frontend/.env.example): VITE_API_BASE_URL=http://localhost:8000/api

   Rules: JWT_SECRET_KEY, HMAC_SECRET and ENCRYPTION_KEY must be three separate
   secrets, never reused. Fail at startup if any is missing or still a placeholder.
   Never log them. Document in the README that changing HMAC_SECRET breaks
   identity lookups for existing records, and losing ENCRYPTION_KEY makes
   encrypted identity data unrecoverable.

2. Tokens: use the two-token flow.
   - Access token: JWT, 15 minutes, sent as a Bearer header, kept in memory in
     the frontend (not localStorage).
   - Refresh token: separate JWT with a distinct 'type' claim, 7 days, set by
     the backend as an httpOnly, Secure (in production), SameSite=Strict cookie.
     Add POST /api/auth/refresh and POST /api/auth/logout (clears the cookie).
     Configure CORS with credentials for the frontend origin.
   - There is NO refresh-token table in the schema and I am not changing the
     schema. Keep refresh tokens stateless. On every refresh, re-check that the
     user exists and users.is_active is true, so deactivating a user cuts them
     off at the next refresh. Note in the README that per-session revocation
     would need a refresh_tokens table, listed under "Schema gaps".
